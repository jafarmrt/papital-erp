# برنامهٔ فروشگاه papitalgallery.com

برنامهٔ جدای سایت فروشگاه (فاز ۸ نسخهٔ ۱۱، مرحلهٔ ۸.۳). صفحه‌ها روی سرور ساخته می‌شوند و همهٔ داده را فقط از Storefront API برنامهٔ ERP می‌خوانند (`/api/storefront/v1`). کلید API فقط روی سرور این برنامه است و به مرورگر نمی‌رسد. برنامه‌های آغاز این کار: `docs/roadmap/V11_STOREFRONT_START_PLAN.md` و `docs/roadmap/V11_STOREFRONT_8_3_PAGES_START_PLAN.md`.

## اجرا روی رایانهٔ توسعه

```bash
cd storefront
npm ci
npm run mock-api          # API نمونه با دادهٔ ساختگی mock/sample روی درگاه 3901
STOREFRONT_API_URL=http://127.0.0.1:3901/api/storefront/v1 STOREFRONT_API_KEY=preview-key npm run dev
```

- برای دادهٔ دیگر، `FIXTURE_DIR` را به پوشه‌ای بدهید که `catalog.json` و پوشهٔ `media/` دارد. `settings.json` و `brand.json` اختیاری‌اند.
- دادهٔ واقعی و عکس‌ها هرگز در این مخزن عمومی گذاشته نمی‌شوند.

## متغیرهای محیط

| نام | کار |
|---|---|
| `STOREFRONT_API_URL` | نشانی Storefront API برنامهٔ ERP |
| `STOREFRONT_API_KEY` | کلیدی که در ERP، در «فروشگاه سایت» → «کلید برنامه سایت» ساخته می‌شود |
| `STOREFRONT_SITE_URL` | نشانی عمومی سایت، برای پیوندهای canonical و کارت شبکه‌های اجتماعی؛ میزبان همین نشانی تنها جایی است که فرم‌های سایت از آن پذیرفته می‌شوند |
| `STOREFRONT_TRUST_PROXY` | با `1` نشانی بازدیدکننده از سرآیندهای وب‌سرورِ جلو (`X-Real-IP`، `X-Forwarded-For`) خوانده می‌شود؛ فقط وقتی بگذارید که آن وب‌سرور این سرآیندها را خودش بازنویسد |
| `STOREFRONT_PORT`، `STOREFRONT_HOST` | جایی که `npm start` گوش می‌دهد (پیش‌فرض: `127.0.0.1:3100`) |
| `STOREFRONT_PREVIEW_NOTICE` | نوار بالای صفحه، فقط در پیش‌نمایش |
| `STOREFRONT_NOINDEX` | با `1` موتورهای جست‌وجو هیچ صفحه‌ای را نمایه نمی‌کنند، مثلاً روی نشانی آزمایشی. بی `STOREFRONT_SITE_URL` یا با نوار پیش‌نمایش هم همین‌طور است. |
| `STOREFRONT_PWA` | با `1` سایت روی گوشی نصب‌شدنی می‌شود (manifest، آیکون‌ها و سرویس‌ورکر). سرویس‌ورکر هیچ صفحه، قیمت یا موجودی‌ای را نگه نمی‌دارد و فقط فایل‌های ساخت، فونت‌ها، آیکون‌ها و عکس‌های محصول را نگه می‌دارد. با خاموش کردن، در بازدید بعدی از گوشی‌ها پاک می‌شود. پیش‌فرض: خاموش. |

## بار روی ERP
همهٔ بازدیدکننده‌ها از راه همین برنامه به ERP می‌رسند، پس سقف درخواست Storefront API (۱۲۰۰ در دقیقه برای هر نشانی) میان همهٔ آن‌ها مشترک است. برای همین برنامه عکس محصولات را پس از اولین خواندن در حافظه نگه می‌دارد (تا ۹۶ مگابایت؛ نام هر عکس هش محتوای آن است و کهنه نمی‌شود)، پاسخ کاتالوگ را چند ثانیه نگه می‌دارد و نشانیِ ناموجود را یک دقیقه به خاطر می‌سپارد. در راه‌اندازی روی سرور (مرحلهٔ ۸.۶) یک کش وب‌سرور جلوی `/media` و `/assets` هم گذاشته می‌شود.

## حساب خریدار و نشانی بازدیدکننده (مرحلهٔ ۸.۴ب)
صفحه‌های `/account/sign-in`، `/account/sign-up`، `/account/set-password` و `/account/sign-out` همه فرم ساده‌اند و بی جاوااسکریپت هم کار می‌کنند؛ فقط صفحهٔ تعیین رمز کلید پیوند را از بخش پس از `#` می‌خواند. نشست خریدار در کوکی `sf_session` است (httpOnly، `SameSite=Lax`، و روی سایت https با `Secure`).

برای هر درخواست حساب، این برنامه نشانی خود بازدیدکننده را با سرآیند `X-Storefront-Client-IP` به ERP می‌دهد تا سقف‌های کد پیامکی و ورود برای هر خریدار جدا شمرده شوند. این نشانی از سرآیند `X-Real-IP` وب‌سرورِ جلوی برنامه خوانده می‌شود، و اگر نبود از آخرین بخش `X-Forwarded-For`. این سرآیندها فقط با `STOREFRONT_TRUST_PROXY=1` خوانده می‌شوند. پس وب‌سرور در راه‌اندازی (مرحلهٔ ۸.۶) باید `X-Real-IP` را خودش بازنویسد (مانند `proxy_set_header X-Real-IP $remote_addr;`) و `STOREFRONT_TRUST_PROXY=1` گذاشته شود؛ اگر وب‌سرور سرآیند را بازننویسد، هر مرورگری می‌تواند نشانی دلخواه بنویسد و سقف‌ها را دور بزند، و بی این متغیر همهٔ خریداران یک سقف مشترک دارند.

فرم‌های حساب فقط از خود سایت پذیرفته می‌شوند: React Router پستی را که `Origin` آن با سایت نخواند رد می‌کند (۴۰۰)، و این برنامه پستی را که مرورگر با `Sec-Fetch-Site` از سایت دیگری بداند (۴۰۳). چون وب‌سرور https را خودش تمام می‌کند و با http به این برنامه می‌رسد، `server.mjs` میزبان `STOREFRONT_SITE_URL` را مبدأ مجاز فرم‌ها می‌گذارد؛ پس وب‌سرور باید سرآیند `Host` را همان‌طور که هست بفرستد (`proxy_set_header Host $host;`).
