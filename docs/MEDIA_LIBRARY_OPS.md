# بهره‌برداری از کتابخانه تصاویر (N-05، v10.1.2)

این راهنما برای کسی است که کارساز را نگه می‌دارد. کاربر عادی با آن کاری ندارد.

## جای پرونده‌ها

- پرونده‌های کتابخانه در پوشه‌ای که متغیر `MEDIA_DIR` در `.env` نشان می‌دهد نگه داشته می‌شوند. اگر این متغیر نباشد، پوشه `media-library` کنار برنامه است (برای نمونه `/opt/papital-erp/media-library`).
- درون این پوشه:
  - `originals/`: پرونده‌ها همان‌طور که فرستاده شده‌اند؛ برنامه هرگز آن‌ها را عوض نمی‌کند.
  - `light/`: نسخه سبک عکس‌ها، با ضلع بلند ۱۶۰۰ پیکسل.
  - `thumbs/`: تصویر کوچک عکس‌ها و تصویر نخست فیلم‌ها.
  - `tmp/`: پرونده‌هایی که در حال بارگذاری‌اند.
- این پوشه در Git نیست (`.gitignore`) و `update.sh` به آن دست نمی‌زند.

## پشتیبان

به تصمیم مالک محصول (۱۹ مهر ۱۴۰۵)، از کتابخانه تصاویر پشتیبانی در Google Drive گرفته نمی‌شود. پشتیبان روزانه (`scripts/backup.sh`) هم این پوشه را نمی‌برد: پایگاه‌داده و `public/uploads` را می‌برد. پس نسخه اصلی هر عکس و فیلم فقط روی دیسک کارساز است. اگر خواستید رونوشتی داشته باشید، پوشه `originals/` را خودتان جای دیگری کپی کنید.

## پس از ارتقا به v10.1.2

۱. **ffmpeg لازم نیست.** به تصمیم ت۱ فیلم نسخه سبک ندارد و تصویر نخست آن را مرورگر می‌سازد؛ چیزی نصب نکنید.

۲. **سقف بدنه پراکسی.** بزرگ‌ترین پرونده‌ای که کتابخانه می‌پذیرد ۵۰ مگابایت است، پس سقف بدنه درخواست در Nginx باید دست‌کم ۵۱ مگابایت باشد. `setup-domain.sh` این سقف را ۶۴ مگابایت می‌گذارد. برای دیدن مقدار کنونی:

   ```bash
   sudo nginx -T 2>/dev/null | grep client_max_body_size
   ```

   اگر چیزی نشان نداد، یا عدد زیر `51m` بود، در بلوک `server` سایت (`/etc/nginx/sites-available/<دامنه>`) این سطر را بگذارید و Nginx را دوباره بارگذاری کنید:

   ```nginx
   client_max_body_size 64m;
   ```

   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

   بدون این سطر، Nginx هر بارگذاری بزرگ‌تر از ۱ مگابایت را رد می‌کند و صفحه خطای «حجم درخواست زیاد است» می‌دهد.

۳. **کتابخانه تصویر `sharp`.** نسخه سبک را کتابخانه `sharp` می‌سازد که `update.sh` با `npm ci` نصب می‌کند و چیز دیگری لازم ندارد.

## صفحه سلامت

«سلامت سامانه» (فقط مدیر سامانه) دو جا از کتابخانه می‌گوید:

- **ذخیره‌سازی پرونده‌ها:** آیا برنامه می‌تواند در پوشه کتابخانه بنویسد.
- **کتابخانه تصاویر:**
  - شمار پرونده‌ها (عکس و فیلم)؛
  - حجم پرونده‌های اصل و حجم نسخه‌های سبک و کوچک. پرونده‌ای که چند بار در کتابخانه آمده یک بار شمرده می‌شود، چون روی دیسک یک نسخه دارد.
  - فضای آزاد دیسکی که کتابخانه روی آن است؛
  - شمار عکس‌هایی که نسخه سبکشان ساخته نشده یا هنوز ندارند.

  کارت در این حالت‌ها «نیازمند رسیدگی» می‌شود:
  - عکسی نسخه سبک ندارد؛
  - فضای آزاد زیر ۵ گیگابایت است؛
  - فضای آزاد زیر یک‌دهم دیسک است.

## ساخت دوباره نسخه‌های سبک

اگر نسخه سبک عکسی ساخته نشده یا پرونده‌اش از دیسک پاک شده، این فرمان را در پوشه برنامه اجرا کنید:

```bash
cd /opt/papital-erp
npm run media:rebuild-light                 # فقط گزارش: چند عکس نسخه سبک ندارند؛ چیزی تغییر نمی‌کند
npm run media:rebuild-light -- --apply      # ساختن آن‌ها
npm run media:rebuild-light -- --all --apply  # ساختن دوباره نسخه سبک همه عکس‌ها
```

- پرونده اصل فقط خوانده می‌شود.
- هر محتوا یک بار ساخته می‌شود و برای همه ردیف‌هایی که آن را دارند ثبت می‌شود.
- اجرای واقعی یک ردیف در گزارش فعالیت‌ها (بخش «کتابخانه تصاویر») می‌نویسد.
- هم‌زمان فقط یک اجرا ممکن است. اجرای دوم می‌گوید یکی دیگر در جریان است و با کد ۲ بیرون می‌آید.
- عکسی که باز هم ساخته نشود، با شماره پرونده و علت در خروجی می‌آید و فرمان با کد ۱ بیرون می‌آید. نسخه سبکی که از پیش داشته سر جایش می‌ماند.
