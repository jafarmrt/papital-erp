# Items, Categories and Prices

Item identity and codes, the Excel import, price lists, categories and transfer designs.

Core rules (one line each, with their guards) are in `AGENTS.md`. This file holds the full rules of the area; the history of each rule (versions, debt rows, decisions) is in `docs/rules/archive/AGENTS_V10.md` at commit `c3c9858` (archives removed in v11.1.0), and a «§N» below refers to that file's numbering.

- **Stock Count and Excel Adjustments Post a Voucher:** A stock count (`audit` document) is recorded only as `final` — a draft is refused and `finalizeDocument` refuses an audit. Its shortages and surpluses are valued at the item's WAC (an item without WAC at 0, never a price-list or sale price), and `syncStockAdjustmentVoucher` (`src/services/accounting/stockAdjustmentVoucher.ts`) issues, in the same transaction, a draft voucher at the Kardex cost against «کسری و اضافات انبار» (7012, mapping `inventoryCountDifferenceAccountCode`), linked by `source_document_id`. Excel stock adjustments of existing items get one such voucher per import; the new Excel items with stock of one import share one draft opening voucher with one debit row per item at its opening Kardex value (`ItemOpeningService.issueImportOpeningVoucher`), and the items of every opening voucher are recorded in `item_opening_voucher_items` (migration 0074, legacy vouchers backfilled from `reference_id`), the one lookup for an item's opening voucher (`itemIdsWithOpeningVoucher`). The item list builds the reservation report only for the items of its own page (`getReservedStocksMap({ itemIds })`) and an Excel import reads and locks the items its file names once, in id order (`ImportItemIndex` in `src/services/items/itemImportIndex.ts`). The item opening voucher (`ItemOpeningService.issueItemOpeningVoucher`, Dr inventory / Cr opening capital) is worth the item's opening Kardex rows — quantity × cost recorded at creation (`openingKardexValue` in `src/services/inventory/itemOpeningValue.ts`) — with or without the item workflow, never current stock × current WAC, and rewrites no Kardex row; an issued opening voucher that differs is only listed by the financial health check (`item_opening_voucher_value`). A new item's opening voucher (`POST /items`, when no item workflow starts) and its audit row are written in the item's own create transaction, so a voucher failure refuses the item and its opening stock. Two active items never share a code (key `upper(btrim(code))`, letter case and surrounding spaces ignored) or a name (key `lower(btrim(name))`): `assertItemCodeAvailable` / `assertItemNameAvailable` (`src/services/items/itemIdentity.ts`) check the item form and the Excel import, and the partial unique indexes `uq_items_code_active` / `uq_items_name_active` (migration 0070, created only on data without duplicates; the financial health check lists duplicates as `item_identity_uniqueness`) turn a concurrent duplicate into the same Persian 409; a new Excel item without a name is a row error. An item's code (the WooCommerce SKU) changes only through `POST /items/:id/change-code` (`changeItemCode` in `src/services/items/itemCodeChange.ts`, permission `products.change_code`, requires `products.edit`, granted to no role): a required reason, the item's version, the code pattern of its type and a free code, under the item row lock, with an `item_code_history` row (migration 0111) and a `CHANGE_CODE` audit row in its transaction; `PUT /items/:id` refuses another code with 422 `ITEM_CODE_CHANGE_SEPARATE`, and the item list offers «تغییر کد» with the earlier codes (`ItemCodeChangeModal`); the site's SKU follows the new code only while «تغییر خودکار کد در سایت» is on, else it is changed by hand. `PUT /items/:id` requires the item's `version` (400 without it) and writes with the version in its WHERE (409 `OCC_CONFLICT` when stale or changed meanwhile); a field missing from the body keeps its current value, the Excel import advances the version too, and the edit and its audit row (before / after / changes) run in one transaction. Saving an item (form, code change, Excel import) moves its code series counter in `item_code_counters` to at least the code's serial under the counter row lock, in the same transaction (`advanceItemCodeCounter` in `src/services/items/itemCodeCounter.ts`; a series without a counter row is left alone), so `/items/next-code` never suggests a saved code. The item form's numbers (reorder point, cost, opening stock per warehouse, weight) go through `decimalInput` and are non-negative (`src/routes/items.schemas.ts`): text is 400, Persian digits are read, and `weight: null` clears the weight (TD-657 item part). Counts before v8.0.3 get no voucher. The stock-count sheet (`GET /documents/audit-items`) resolves its location by warehouse code or name like a document (`createWarehouseResolver`, empty = default warehouse, unknown = 422) and the page selects warehouses by code; each posted line carries the book stock the sheet showed (`system_stock`), and a count whose shown book stock differs from the stock under the item locks is refused with 409 `AUDIT_BOOK_STOCK_CHANGED` listing the items, nothing moves and the sheet reloads (`assertBookStocksUnchanged` in `src/services/inventory/stockCountSheet.ts`). Every count line carries its count and each (item, warehouse) has one line: a line without `physical_stock` (missing or empty) is 422 `AUDIT_COUNT_MISSING` and a repeated (item, warehouse) 422 `AUDIT_DUPLICATE_LINE`, before any movement (`assertStockCountLines`, same file); the document view (`GET /documents/:id`) keys each line's variance by item and warehouse over the document's active, non-reversal Kardex rows (`stockCountVariances`). The Excel import never changes the WAC of an item that has stock: such a row is not applied and is listed in the import errors; a value within 1 rial of the current WAC (`EXCEL_WAC_TOLERANCE`) counts as unchanged and the current WAC is kept; an item without stock takes the file's WAC.

- **Item Excel Import and Price Lists:** Only the configured price lists (`pricing_strategies`) are prices: the unified Excel import, the pricing page quick import (`buildQuickPriceUpdates` in `src/lib/items/quickPriceImport.ts`) and `POST /items/:id/prices` / `batch-update` read price columns through `extractRowPriceColumns` / `priceListMatcher` (`src/lib/items/excelPriceColumns.ts`); another «قیمت …» column is a row error and is ignored, and setting a price for an unconfigured title is 422 `PRICE_LIST_NOT_CONFIGURED` (deleting one is allowed). The cost column is «میانگین موزون بها» (`ITEM_WAC_COLUMN`; old WAC headers are still read as cost, never as a price). `filterActivePrices` returns configured price lists only. Migration 0068 soft-deleted the active rows titled «میانگین خرید (WAC)», «موجودی کل» and «میانگین بهای خرید» and recorded them in `item_price_title_cleanup`; other unknown titles are only listed by the financial health check (`item_price_unknown_title`). An import never rewrites a price that is already the only active price of its list with the same amount and currency, and such a price is not counted in `pricesCount`; the price history shows when each row was created (`priceHistoryRegisteredAt`, `created_at` with a `Z`). Each price list has its own currency column «ارز - قیمت <title>» in the item export, the pricing page export and the import template, and the unified and quick imports read it first (`priceCurrencyColumn` / `priceExportCells` in `src/lib/items/excelPriceColumns.ts`); a legacy row-wide «واحد ارز» is read only for a list without its own column. The import template comes from the server (`GET /items/excel-template`, `buildItemExcelTemplate` in `src/services/items/itemExcelTemplate.ts`): one sample row with the columns the import reads, 10 in each active warehouse and «موجودی کل» their sum, and every configured price list with its currency column; it reads no item and writes no export audit row. The items and pricing pages show each button and price field by the permission of the server route it calls (`products.create` / `products.edit` / `products.delete`, `woocommerce.manage`, `products.edit_price`), never by a role code; the average cost is always shown in IRR, and the pricing page's margin badge and markup buttons compare only rial prices with it (`priceMarginPercent` / `markupPrice` in `src/lib/items/priceMargin.ts`). Each part of the import needs its own permission, computed in the route with `can()` and passed to `importItemsFromExcel` (`src/services/items/itemExcelImport.ts`) as `ItemImportPermissions` (`src/lib/items/itemImportPermissions.ts`), never read from the body: a new item with its opening stock `products.create`, fields of an existing item `products.edit`, prices `products.edit_price`, a stock increase of an existing item `warehouse.in` and a decrease `warehouse.out`; a part the user may not change is a row error and is skipped only when it would change something, and the Excel window says so before upload. For an existing item a missing column or blank cell means unchanged and the type comes from the item unless the row has a type column; the page filter only sets a new item's type, and the code format is checked only for a new item, in the browser preview with the server's patterns (`codeFormatError` in `src/lib/items/itemCodeFormat.ts`). The type cell is read by `parseItemTypeCell` (`src/lib/items/itemExcelCells.ts`, shared by the server and the preview): «ماده اولیه» / «مواد اولیه» / `raw_material` and «محصول نهایی» / «محصول» / `product`; any other word is a row error naming the column, and the preview resolves a new item's type with the server's rule (`newItemTypeOf`). Cost, reorder point, weight and stock cells are read by `parseNumberCell` (same file): an Excel number as is, text with Persian or Arabic digits, «٫» and thousands separators through `normalizeDecimalString`, and any other text is a row error naming the column, also shown by the preview. A row that raises the stock of an item left without a weighted average cost (a new item with an empty or zero cost cell, or an existing item without cost) is a row error naming the cost column and writes nothing (`stockWithoutCostError` in `src/services/items/itemExcelRow.ts`; the preview marks such a new item with `newItemStockWithoutCost`), while a count decrease is still recorded at cost 0. A row finds its item by code only (`ImportItemIndex.findByCode`: the exact code, else the single item whose code differs only in letter case; several such items are a row error; else the live item that held it as an earlier code), a name held by another active item is a «نام تکراری» row error for new and existing items alike, and the import never changes an item's code. Stock columns are planned before anything is written (`planStockChanges` in `src/services/items/itemExcelRow.ts`): a warehouse column sets only that warehouse and a filled «موجودی کل» must equal the sum of all warehouses; «موجودی کل» alone is accepted only for a new item (default warehouse) or an item whose whole stock is in the default warehouse, an equal total is unchanged, otherwise the row is refused («موجودی هر انبار لازم است»); a negative quantity or a change in an inactive warehouse is a row error, and a refused row writes nothing. Every item the import creates or changes gets one «کالا» audit row (CREATE / UPDATE) with before / after / changes of its fields, `موجودی <warehouse code>` and `قیمت <title>` (`itemAuditSnapshot` / `logItemImportChange` in `src/services/items/itemExcelAudit.ts`), plus one IMPORT summary row, all written with the import's `tx`. The pricing page and `POST /items/:id/prices` write prices only through `ItemPricingService.applyPriceWrites` inside the caller's transaction: it locks the items with `lockStockItems` before reading their active prices, so each price list of an item keeps one active price, an unchanged price is not rewritten, and the audit row is written with the same `tx`; older duplicates are only listed by the financial health check (`item_price_duplicate_active`). A price is a decimal above zero (Persian digits accepted) in a currency of the §6 list (`parsePriceAmount` / `priceCurrencyOf` in `src/lib/items/priceInput.ts`, shared by the routes, the Excel import, the quick import and the pricing page): `POST /items/:id/prices` and `batch-update` refuse anything else with 400, `batch-update` removes a price only with `remove: true` (the pricing page sends it for an empty field and never sends an invalid amount), and an invalid price or currency refuses the whole Excel row; older rows are only listed by the financial health check (`item_price_invalid_amount_currency`).

- **22 Categories:** `DEFAULT_CATEGORIES` (`src/data/defaultCategories.ts`) is the one list: 9 product categories (گردنبند، گوشواره میخی، گوشواره آویز، انگشتر، دستبند، گوشواره آویز بزرگ، گردنبند بزرگ، گوشواره دو تکه، گردنبند دو تکه) and 13 raw_material categories (ترنسفر، مهره، مهره کریستالی، سنگ، مهره حدید، مهره چوبی، خرج کار، خرج کار طلایی، خرج کار برنزی، خرج کار استیل، بند چرمی و زنجیر، «کیلر، رنگ، گلیز»، سایر اقلام); the boot seed and «بازگردانی دسته‌های پیش‌فرض» read it.

- **Category Changes:** A category is soft-deleted (`categories.is_deleted`, migration 0072) and the list reads only live ones; a category that active items use is not deleted (422). Create, edit, delete and the default reset run in one transaction with a «دسته‌بندی کالا» audit row (before / after / changes) through `src/services/items/itemCategory.service.ts`; the reset restores a deleted default category instead of adding a second row. A live category name is unique by `lower(btrim(name))` (`assertCategoryNameAvailable` in `src/services/items/itemCategoryIdentity.ts`, partial unique index `uq_categories_name_active`, migration 0073, created only on data without duplicates; a concurrent duplicate is the same Persian 409). Items point to their category by name, so a rename moves the category's active items to the new name in the same transaction (items locked in id order, each item's version advanced, the item ids in the audit row) and a type change of a category with active items is 422 `CATEGORY_TYPE_HAS_ITEMS`; the default reset keeps such a category's type. Old duplicate names and active items whose category no longer exists are only listed by the financial health check (`category_name_uniqueness`).

- **Auto-Fill Default Units:** When category is selected in `ItemFormModal.tsx`, unit automatically updates to category's `defaultUnit` (جفت، ریسه، برگ، متر، عدد و...).

- **Dual-Route API:** Transfer routes in `src/routes/transfers.routes.ts` accept both `POST` and `PUT` across `/transfers` and `/transfers/:code`. A transfer code has one row: saving a soft-deleted code revives that row under its row lock in one transaction, `GET /transfers/:code` answers 404 for a deleted design no product uses, and the page reads every code (`/transfers?all=true`). Since v10.0.182 `GET /transfers` answers one page of codes (`page`, `limit` at most 200, `search` over code, title, notes and the linked products' names and codes, `image`) with only that page's products and a `summary` of every code, all in SQL (`listTransferCodes` in `src/services/transfers/transferCodeList.ts`, contract `src/lib/transfers/transferCodeList.ts`), and the page reads one page at a time.
