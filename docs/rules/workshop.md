# Workshop Cartable

The workers' phone cartable: tasks, end-of-task reports and deliveries.

Core rules (one line each, with their guards) are in `AGENTS.md`. This file holds the full rules of the area; the history of each rule (versions, debt rows, decisions) is in `docs/rules/archive/AGENTS_V10.md`, and a «§N» below refers to that file's numbering.

- **Workshop Cartable Data:** three catalog keys, `workshop.self` (a worker's own cartable), `workshop.review` (requires `projects.view`; a project manager reviews end-of-task reports) and `workshop.long_session` (requires `workshop.self`), in `src/lib/permissions/workshopPermissions.ts`, and the role template «همکار کارگاه» (`workshop_worker`; named «کارکن کارگاه» before v10.1.69, and a role already made keeps its stored name). A login, its token and its cookie last seven days for a role whose stored permissions hold `workshop.long_session` and no key outside `LONG_SESSION_ROLE_KEYS` (`workshop.self`, `workshop.long_session`), else 24 hours, the system admin included (`sessionLifetimeSeconds` in `src/lib/auth/sessionLifetime.ts`, `sessionLifetimeOfRole` in `src/middleware/auth.ts`); a permission change of a role that holds or held the key ends its users' sessions (`updateRole`, token version). «مسئولان پروژه» (`project_managers`, migration 0119) are saved by `POST` / `PUT /projects` (`managerUserIds`, missing = unchanged on edit) in the project's transaction after its row, audited with `tx`, and returned as `managers` with the project record; a missing, deleted or repeated user among the newly added ones is 422 `PROJECT_MANAGER_INVALID` (a manager deleted later never blocks the save) (`setProjectManagers` in `src/services/projects/projectManagers.ts`). A remittance (`documents.recipient_personnel_id`) and a material allocation (`project_bom_allocations.recipient_personnel_id`) keep their recipient personnel (`recipientPersonnelId`): only a remittance takes one (422 `RECIPIENT_REMITTANCE_ONLY`), and it is a live personnel who has not left, read `FOR SHARE` (else 422 `RECIPIENT_PERSONNEL_INVALID`, before any movement; rule in `src/lib/workshop/recipient.ts`), and the stock page sends a terminated counterparty only as the buyer name (`isRecipientCandidate`). Migration 0119 also creates `stock_receipt_confirmations` (one answer per remittance or allocation) and `workshop_task_reports` (one live report per schedule row, `uq_workshop_task_reports_live_row`) and the reminder dedup index `uq_notifications_workshop_reminder`, which the cartable routes of part 2 use.

- **Workshop Cartable Server:** `src/routes/workshop.routes.ts` with services in `src/services/workshop/`. A worker (`workshop.self`, acting only as the live personnel linked to the user, else 422 `WORKSHOP_PERSONNEL_NOT_LINKED`) reads their open schedule rows of open projects with the deadline (`GET /workshop/my-tasks`, never an amount before approval, ت۷) and their final remittances and allocations (`GET /workshop/my-deliveries`), answers each delivery once (`POST /workshop/deliveries/confirm`: «تحویل گرفتم» or «مغایرت دارد» with a required note, notifying the recorder and `warehouse.out` holders; stock never changes, ت۱) and reports a row's final quantity (`POST /workshop/reports`, at most the row's quantity, one live report per row, edit and withdraw only while submitted, OCC by `version`; ت۵). Approve and reject (`workshop.review`) need the user on the project's managers, else 403 `WORKSHOP_NOT_PROJECT_MANAGER`, and never a report of their own work (its personnel linked to them or recorded by them, 403 `WORKSHOP_OWN_REPORT`; the system admin is exempt); under the project then report row locks the approval writes the work log through `PieceworkService.logWorkEntries` with the schedule row link and the server rate, the quantity correctable (ت۲), notifies the worker with the amount and suggests the progress matrix tick when every row of that product and stage has a live log (ت۶); a rejection needs a reason. Every write has its audit row with `tx`. The bell reminds a worker once the day before a deadline and once after it (`generateWorkshopDueReminders`, `uq_notifications_workshop_reminder`, ت۸), scanning at most once an hour per user outside any transaction (`takeWorkshopReminderScan` in `src/lib/workshop/reminderThrottle.ts`). A row without a planned quantity above zero takes no report, edit or approval (422 `WORKSHOP_ROW_QUANTITY_MISSING`, `reportQuantityError`); edit and approve re-read the row under the project lock, a row gone or reassigned is 422 `WORKSHOP_ROW_NOT_FOUND` and a row whose task changed since the report 409 `WORKSHOP_ROW_TASK_CHANGED`; live work logs of the same personnel, task and project that no schedule row links come with each review item (`manualLogs`, `manualWorkLogs`) and approval refuses them with 409 `WORKSHOP_MANUAL_LOGS_EXIST` unless acknowledged («بررسی کردم», since v10.1.40 the ids the reviewer saw, below); deleting an approved report's work log or moving it to another project turns the report «ردشده» with a note in that transaction (`revertWorkshopReportsOfLog` in `src/services/piecework/workshopReportRevert.ts`), and the stage progress counts each schedule row's live work log, an approved report's or one the project recorded from the schedule.

- **Workshop Cartable Pages:** one page, `src/pages/WorkshopPage.tsx`, with tabs (`src/lib/workshop/workshopView.ts`): `/workshop` (`workshop.self`) shows «کارهای من» (deadline colour, a reminder's `?row=` card first, the end-of-task report sheet with the quantity checked by the server's `reportQuantityError`, edit and withdraw while waiting, and the approved reports with their amount) and «حواله‌های من» (`?tab=deliveries`; «مغایرت دارد» needs a note); `/workshop/review` (`workshop.review`) lists the waiting reports with approve (corrected quantity, work date; the manual work logs of the same task listed and «بررسی کردم» required before approving) and reject (reason), and after the last row offers the progress matrix tick only to a holder of `projects.edit`, never ticking for them. Every window is `WorkshopSheet` (`src/components/workshop/`): a full-screen phone sheet whose actions are off while offline (`OFFLINE_SUBMIT_TITLE`) and whose Esc and close do nothing while it saves. Both pages have `PAGE_ACCESS` rows, menu items and one phone bar button «کارگاه» that opens the review page for a manager without `workshop.self` (`fallbackPath` in `mobileNavItems.ts`); the project's schedule tab shows each stage's approved share and the waiting reports (`ProjectWorkshopPanel`, `GET /workshop/projects/:projectId/reports`). Reads and writes go through `src/hooks/queries/useWorkshopQueries.ts`; nothing is cached for offline use. The approval sends the manual work logs it showed as `acknowledgedManualLogIds`, and the server refuses with 409 `WORKSHOP_MANUAL_LOGS_EXIST` when the live set differs (`sameIdSet` in `src/services/workshop/workshopReports.ts`); a report turned «ردشده» because its work log was deleted or moved notifies its worker (`workshop_report_reverted`), and the bell's reminder scan starts its hour only after a scan that succeeded (`runThrottledReminderScan` in `src/lib/workshop/reminderThrottle.ts`).
