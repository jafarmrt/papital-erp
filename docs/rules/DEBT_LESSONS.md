# Debt Lessons

What the fixed debt of series 1 to 10 teaches, in one place, and the debt rows closed since series 11. The core rules (`AGENTS.md`) and the area files (`docs/rules/*.md`) already hold most lessons as rules; this file keeps only the patterns that kept coming back and that no single rule names. Each lesson cites a few of the rows it comes from; their full text is in `docs/rules/archive/TECH_DEBT_ARCHIVE_V10.md` (frozen, series 1 to 10). Reviewers check a change against this list.

## Lessons

1. **One action, many paths.** A guard, a voucher or a limit added to one path is missing from the others that reach the same effect: a workflow transition, an Excel import, an item edit, a project delivery or a procurement shortcut. Before closing a finding, list every route, workflow action and bulk tool that causes the same change and give each the same check. (TD-904, TD-689, TD-648, TD-305, TD-285, TD-286, TD-287, TD-443)
2. **The screen and the server disagree on the payload.** Forms sent field names, units or codes the server did not read (`requestedQty` for `quantity`, a warehouse name for its code, no currency or rate, no paging parameters), and reports read totals the server never sent; each failed silently as 400, zero or «nothing found». Test a write with the exact body the form builds and a report with the exact answer the server returns. (TD-688, TD-480, TD-564, TD-565, TD-563, TD-735)
3. **A stock value change without its voucher.** Every path that changes stock quantity or cost needed its accounting voucher in the same transaction; the ones that did not (project delivery, BOM allocation, a zero-total invoice, stock counts, Excel stock fixes) split stock value from the inventory accounts. The three-way and stock-value invariants are the check. (TD-285, TD-286, TD-287, TD-906, TD-772, TD-255, TD-262)
4. **Check, then act, without a lock.** A status or a quantity read before the transaction let two requests both pass: a request received twice, a voucher reversed twice, a deleted cheque cashed, a bank balance rewritten while a payment ran. Re-read the row under its lock inside the transaction, and check `is_deleted` and the status there. (TD-326, TD-327, TD-321, TD-322, TD-340, TD-320)
5. **Undoing what depends on something else.** A void accepted while a return, a reversal or the other side of a transfer still pointed at the document; a reversal row could itself be reversed. A void refuses while an active dependent exists, and a reversal row is never voided. (TD-773, TD-499, TD-341, TD-500)
6. **Every derived amount has a ceiling.** A return beyond what was sold, a line discount above the line, a negative bonus or deduction, a delivery beyond the project quantity: each is bounded by its source document, on the server. (TD-253, TD-788, TD-380, TD-804, TD-327)
7. **A soft-deleted name or code comes back to life.** Creating a user, an account or a customer with the code or name of a soft-deleted row revived that row with its history, secrets and balances. A new record never reuses a deleted row. (TD-519, TD-546, TD-703)
8. **Finding a row by text that is not unique.** A cheque number, a «name contains» match or a reference text found other people's rows. Rows are found by id and type only. (TD-271, TD-416, TD-548, TD-497)
9. **State kept only in the browser.** A «registered» flag in memory, a role preselected in a form, a query cache that survives logout: the server is the only source of truth, and logout or a 401 clears the cache. (TD-736, TD-517, TD-518)
10. **An error swallowed reads as success.** A caught workflow start, a failed customer insert only logged, a backup or an update reported «successful» from a step that proves nothing, a restore drill that compared a count with itself. On a write path no catch continues as if nothing happened, and a check verifies the result, never only that a process is alive. (TD-451, TD-703, TD-361, TD-362, TD-365)
11. **Calendar edges.** A Jalali leap year has 30 Esfand, and a year is closed only after it ends; tests cover both. (TD-310, TD-543, TD-544)
12. **Migrations on real data.** A data migration over a large table hit the request timeout, two starts ran it twice, an out-of-order `when` skipped it silently in production, and a NOT VALID constraint broke a later migration. Migrations run under the advisory lock with their own timeout, and an upgrade is tested from the oldest supported version. (TD-366, TD-364, TD-368)
13. **Keys built from input are bounded.** A metrics label from the raw request path grew without end. Any cache key, label or map entry built from request input has a fixed set of values or a cap. (TD-582)
14. **CI that depends on anonymous registries.** Database and Node images pulled anonymously failed when the pull limit was reached, before any test ran. CI pulls from a mirror or with a login. (TD-1169)
15. **Purchase discounts reach the cost.** A line discount lowered the voucher but not the weighted average cost or the Kardex row, so stock value drifted above the inventory accounts. (TD-250)
