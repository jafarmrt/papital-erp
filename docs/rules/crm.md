# Customer Relations

Sales files, activities and their attachments.

Core rules (one line each, with their guards) are in `AGENTS.md`. This file holds the full rules of the area; the history of each rule (versions, debt rows, decisions) is in `docs/rules/archive/AGENTS_V10.md`, and a «§N» below refers to that file's numbering.

- **Sales File and Activity Attachments:** A sales file (`crm_leads`) and an activity or follow-up (`crm_activities`) take image and PDF attachments through `GET` (`crm.view`), `POST` (`crm.manage`, the raw file body with `X-File-Name`) and `DELETE` on `/crm/leads/:id/attachments` and `/crm/activities/:id/attachments` (`src/routes/crmAttachments.routes.ts`, `CrmAttachmentService` in `src/services/crm/crmAttachments.service.ts`): JPG, PNG, WEBP or PDF whose content matches its type, at most 10 files per record and `MAX_ATTACHMENT_FILE_MB` per file (422 `CRM_ATTACHMENT_FORMAT` / `CRM_ATTACHMENT_TOO_LARGE` / `CRM_ATTACHMENT_LIMIT`; the rule is shared with the browser in `src/lib/crm/crmAttachments.ts`). They are stored through `file_attachments` (entity `crm_lead` / `crm_activity`, read permission `crm.view`) with the original kept and, for an image, a light WEBP of long side `MEDIA_LIGHT_LONG_SIDE` made by the media library's sharp pipeline (`file_attachments.light_storage_path`, migration 0127, served with `?variant=light`); each addition and removal is written under the record's row lock with its audit row in the same `tx`, and the files never enter the media library. The sales file window and each activity's paperclip button show them (`CrmAttachmentsPanel`), and a window does not close while a file is being sent or removed.
