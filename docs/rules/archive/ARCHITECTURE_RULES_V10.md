# قوانین بنیادین معماری سامانه (ARCHITECTURE_RULES.md)
> **وضعیت سند:** 🔒 **تخلف‌ناپذیر و الزامی (Mandatory Architecture Invariants)**  
> تمامی توسعه‌دهندگان و ایجنت‌های هوش مصنوعی (AI Agents) موظف به رعایت بی‌قیدوشرط این ۱۰ قانون در تمام تغییرات کد هستند.

---

### RULE 01: Routes Never Mutate Database Directly (Thin Controllers)
روتها (Controllers/Routes) صرفاً وظیفه دریافت درخواست، اعتبارسنجی ورودی (Validation via Zod)، استخراج اطلاعات کاربر/نشست و صدا زدن متدهای لایه سرویس (Domain Services) را دارند. هیچ کوئری `insert`, `update`, `delete` یا کوئری‌های پیچیده بیزنسی نباید مستقیماً در فایل‌های روت نوشته شود.

### RULE 02: Separation of Stock Kardex vs Financial Accounting
جدول `transactions` در دیتابیس، **دفتر کل کاردکس انبار (Stock Kardex Ledger)** است و هیچ ارتباط مستقیمی با تراکنش‌های مالی ندارد. تمام عملیات انبارداری، کاردکس و محاسبات بهای تمام‌شده میانگین موزون (WAC) باید از طریق `DocumentService.applyStockMovement` یا متدهای اختصاصی انبار مدیریت شوند؛ اسناد مالی و دوبل حسابداری منحصراً در جداول `journal_vouchers`, `journal_voucher_items`, `treasury_transactions` و سرویس‌های حسابداری (`src/services/accounting/`) نگهداری می‌شوند.

### RULE 03: Atomic Multi-Domain Transactions (DB-008 Invariant)
هر عملیاتی که چندین دامنه را تحت تأثیر قرار می‌دهد (مانند ثبت فاکتور نهایی که همزمان کاردکس انبار را تغییر داده و سند دوبل مالی صادر می‌کند) **باید درون یک تراکنش واحد دیتابیس (`tx`) اجرا شود**. شیء `tx` باید به طور صریح به زیرمتدها پاس داده شود تا در صورت شکست هر بخش، کل تراکنش Rollback شود و داده‌های نیمه‌کاره یا ناسازگار در دیتابیس باقی نماند.

### RULE 04: No Raw SQL for Mutations (Read-Calculate-Update)
جهش اطلاعات دیتابیس (Insert/Update/Delete) با استفاده از Raw SQL یا متدهایی مانند `tx.execute(sql`...`)` اکیداً ممنوع است (جهت پیشگیری از خطای `operator is not unique` در درایور PostgreSQL). محاسبات همواره باید در حافظه توسط کدهای تایپ‌اسکریپت انجام شده و تغییرات با متدهای استاندارد Drizzle ORM مانند `tx.update().set(...)` ذخیره شوند.

### RULE 05: Atomic Sequence Generation for Business Identifiers (DB-001)
تولید شماره‌های تجاری، شماره سندهای مالی، شماره عطف فاکتورها و کدهای ترتیبی هرگز نباید با استفاده از الگوهای مستعد تداخل همزمانی مانند `MAX() + 1` یا `COUNT(*)` انجام شود. همواره باید از توالی‌های PostgreSQL (`SELECT nextval(...)`) یا جداول شمارنده اتمیک تحت قفل/آپدیت اتمیک (`document_ref_counters`, `item_code_counters`) استفاده گردد.

### RULE 06: Runtime Validation Contracts (Zod Guardrails)
تایپ‌های تایپ‌اسکریپت فقط در زمان کامپایل وجود دارند. تمامی اندپوینت‌های حساس مالی، اسناد و انبار باید داده‌های ورودی را قبل از ارسال به لایه سرویس با استفاده از اسکیمای Zod اعتبارسنجی کنند تا از ارسال مقادیر منفی، آرایه‌های خالی، تایپ‌های نادرست یا آبجکت‌های ناقص جلوگیری شود.

### RULE 07: Array Guarding & Standard Response Protocol
پاسخ تمام APIها در سمت سرور باید ساختار مشخص داشته باشد و در سمت کلاینت، تمامی آرایه‌ها قبل از فراخوانی متدهایی نظیر `.map()`, `.filter()`, `.reduce()` باید از گارد آرایه عبور کنند:
```ts
const safeList = Array.isArray(data) ? data : [];
```

### RULE 08: Domain Ownership & Module Boundary Integrity
هر ماژول مالک انحصاری جداول و داده‌های خود است. هیچ ماژولی نباید بدون استفاده از سرویس ماژول مقصد یا تراکنش مشترک هماهنگ‌شده، داده‌های سایر ماژول‌ها را دستکاری کند. وابستگی‌های چرخشی بین ماژول‌ها باید از طریق ارکستریتورها یا رویدادهای دامنه (Domain Event Bus) برطرف شوند.

### RULE 09: Soft Deletes & Reversal Transactions for Auditable Entities (DB-009)
اسناد مالی، آرتیکل‌ها، حرکات انبار و تراکنش‌های خزانه هرگز به صورت فیزیکی از دیتابیس حذف (Hard Delete) نمی‌شوند. هرگونه ابطال یا اصلاح از طریق تنظیم `is_deleted = 1` و در صورت نیاز، صدور رکورد معکوس اتمیک با ارجاع به رکورد اصلی (`reversal_of_id`) انجام می‌پذیرد تا زنجیره ردیابی حسابرسی همواره حفظ شود.

### RULE 10: Decluttered UI & Natural Persian Terminology
رابط کاربری باید از اصل خلوت‌سازی تبعیت کند. ردیف‌های شلوغ و متراکم دکمه‌ها ممنوع است؛ اکشن‌های ثانویه در منوی کشویی سه‌نقطه قرار گیرند. تمام واژگان، عناوین و پیام‌ها در محیط کاربری باید به فارسی سلیس، محترمانه و دقیق بازار مالی ایران باشند و استفاده از اصطلاحات فنی انگلیسی یا اختصارات مبهم (FSM, SoD, Kardex, Draft, Reversal, Sync) در UI برای کاربر ممنوع است.
