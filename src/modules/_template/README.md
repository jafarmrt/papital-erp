# 📦 راهنمای توسعه ماژول‌های جدید (Papital ERP Module Template)

این دایرکتوری (`src/modules/_template/`) شابلون مرجع و استاندارد معماری برای توسعه ماژول‌های جدید در سامانه ERP بر مبنای قوانین معماری نسخه ۴ (`AGENTS.md` و `ARCHITECTURE_RULES.md`) است.

---

## 🏗️ ساختار ماژول استاندارد

```text
src/modules/[module_name]/
├── schema.ts         # تعاریف جداول Drizzle ORM، ایندکس‌ها، نگارش و فیلدهای حذف منطقی
├── types.ts          # تایپ‌ها و اینترفیس‌های دامنه (DTOها، فیلترها و پاسخ‌ها)
├── validation.ts     # قراردادهای اعتبارسنجی زمان اجرا با کتابخانه Zod
├── service.ts        # متدهای دامنه و بیزینس لاجیک بر پایه الگوی Read-Calculate-Update
├── routes.ts         # روت‌های اکسپرس همراه با میدل‌ورهای احراز هویت، مجوز، ولیدیشن و ایدمپوتنسی
├── index.ts          # نقطه ورود و Export یکپارچه ماژول
└── README.md         # مستندات اختصاصی دامنه
```

---

## 📋 چک‌لیست ایجاد یک ماژول جدید

هنگامی که می‌خواهید یک ماژول جدید (مثلاً ماژول مدیریت دارایی‌ها `asset_management` یا ماژول لجستیک `logistics`) ایجاد کنید، مراحل زیر را گام‌به‌گام دنبال کنید:

### ۱. کپی دایرکتوری شابلون
دایرکتوری `src/modules/_template/` را به مسیر ماژول جدید کپی کنید:
```bash
cp -r src/modules/_template src/modules/your_module_name
```

### ۲. تعریف اسکیما (`schema.ts`)
- نام جدول و ستون‌ها در دیتابیس باید به صورت `snake_case` باشد.
- فیلدهای پولی و اعشاری با `numeric({ precision: 18, scale: 4, mode: 'number' })` تعریف شوند.
- فیلد `isDeleted` با پیش‌فرض `0` و فیلد `version` با پیش‌فرض `1` (برای OCC) لحاظ گردند.
- ایندکس‌های مناسب برای کلیدهای جستجو و فیلترها تعریف شوند.
- سپس اسکیما را در `src/db/schema/index.ts` اکسپورت نمایید.

### ۳. تعریف تایپ‌ها (`types.ts`)
- اینترفیس‌های اصلی موجودیت (`Entity`)، ایجاد (`CreateDTO`)، ویرایش (`UpdateDTO`) و فیلترهای صفحه‌بندی (`FilterDTO`) را مشخص کنید.

### ۴. قراردادهای اعتبارسنجی (`validation.ts`)
- برای بدنه درخواست (`body`)، پارامترهای آدرس (`params`) و فیلترهای جستجو (`query`) اسکیماهای Zod ایجاد کنید.
- محدودیت‌های مثبت بودن مبالغ (`.nonnegative()`) و سقف مجاز صفحه‌بندی (`limit <= 100`) را فراموش نکنید.

### ۵. پیاده‌سازی سرویس بیزینس لاجیک (`service.ts`)
- جهش داده‌ها باید صرفاً از طریق Drizzle ORM و درون تراکنش (`tx`) انجام شود (**هیچ‌گاه از Raw SQL برای INSERT/UPDATE استفاده نکنید**).
- الگوی **Read-Calculate-Update** را با قفل سطری `.for('update')` رعایت کنید.
- قبل و بعد از تغییرات، متد `logActivity` را برای ثبت لاگ ممیزی فراخوانی نمایید.
- در صورت نیاز به رویدادهای سیستمی، رویدادها را از طریق `DomainEventBus` یا `OutboxService` منتشر کنید.

### ۶. تنظیم روت‌ها (`routes.ts`)
- تمام اندپوینت‌ها باید با `asyncHandler` کپسوله شوند.
- میدل‌ورهای `authenticateToken`، `authorize(...)` و `validate(...)` را به درستی اعمال کنید.
- برای روت‌های ایجاد و تراکنش‌های حساس، میدل‌ور `idempotency` را فعال کنید.
- خروجی‌ها را با پشتیبانی از هر دو فرمت `camelCase` و `snake_case` (فرمت دوگانه) بازگردانید.

### ۷. رجیستر کردن روت در سرور (`src/app.ts`)
روت ماژول را در فایل اصلی اپلیکیشن ثبت کنید:
```ts
import yourModuleRoutes from './modules/your_module_name/routes.js';

app.use('/api/your-module-entities', yourModuleRoutes);
```

### ۸. اضافه کردن تست‌های یکپارچگی
برای ماژول جدید، یک سوئیت تست اختصاصی در مسیر `src/tests/suites/` ایجاد کرده و به `src/tests/testRunner.ts` معرفی نمایید.

## 🔒 قوانین تخلف‌ناپذیر معماری (V4 Non-Negotiable Rules)
1. **عدم استفاده از Raw SQL برای جهش داده:** همواره از متدهای Drizzle استفاده کنید.
2. **عدم بلعیدن خطاها:** خطاها باید از نوع کلاس‌های استاندارد (`ValidationError`, `NotFoundError`, `ConflictError`) پرتاب شوند.
3. **عدم ذخیره توکن در کلاینت:** احراز هویت صرفاً مبتنی بر کوکی HttpOnly امن است.
4. **ثبت چنج‌لاگ:** پس از اتمام هر ماژول یا تغییر ساختاری، چنج‌لاگ در `src/data/changelogs/4.ts` به‌روزرسانی شود.
